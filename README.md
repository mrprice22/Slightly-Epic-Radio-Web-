# Slightly Epic Radio — Web Player

A small embeddable internet-radio player: station dropdown, play/pause, volume slider, station logo and live "now playing". It plays the same stations as the [Android](https://github.com/mrprice22/Slightly-Epic-Radio-Android-) and [Roku](https://github.com/mrprice22/Slightly-Epic-Radio-Roku-) apps, and its station list is written by the [Station Manager](https://github.com/mrprice22/Slightly-Epic-Radio-Manager-).

Demo and embed code: **https://mrprice22.github.io/Slightly-Epic-Radio-Web-/**

## Embedding

```html
<iframe class="slightly-epic-radio"
        src="https://mrprice22.github.io/Slightly-Epic-Radio-Web-/player.html"
        width="100%" height="84" style="border:0;max-width:560px"
        title="Slightly Epic Radio" allow="autoplay; encrypted-media"></iframe>
```

- At 440px wide or more, the player is one row and `height="84"` fits. Narrower embeds put the volume slider on its own row, so they need `height="124"`.
- Instead of a fixed height, you can use the auto-height snippet on the demo page. The player posts its height to the parent page as `{type: 'slightly-epic-radio:height', height}`.
- The player also posts every playback state change as `{type: 'slightly-epic-radio:state', state}`, where `state` is `idle`, `loading`, `playing`, `resume` or `error`. A site can use it for its own indicator, such as a minimized icon that glows while music plays.

| URL parameter | Example | Effect |
|---|---|---|
| `default` | `?default=zen-garden` or `?default=15` | Starting station for **first-time** visitors (title slug or id). Returning visitors get the station they last listened to. |
| `station` | `?station=zen-garden` | **Forces** the starting station, even over the visitor's last station. |
| `size` | `?size=slim` | One-row 54px bar for docking along the bottom of every page of a site. Below 440px wide, the speaker button swaps the station line for the volume slider. |
| `frame` | `?frame=none` | No panel background, border or outer padding, so the player blends into the host page's own bar (e.g. inside a site's nav menu). |
| `resume` | `?resume=0` | Turns off carrying playback over to the next page load (on by default). |
| `theme` | `?theme=dark` | `light`, `dark` or `auto` (the default, which follows the visitor's system setting). |
| `accent` | `?accent=c8a045` | Hex accent color. |

**Which station it starts on:** the first of these that applies wins:
1. Playback carried over from the previous page
2. `station=`
3. The visitor's last station
4. `default=`
5. The first station

The visitor's station and volume live in the player's localStorage. Browsers keep an embedded player's storage separately for each site it's embedded on, so each of your sites remembers its own visitors' choice. No cookies are involved.

### Multi-page sites

On a site where every link loads a new page, the player in the new page is a fresh copy. So it hands playback over:

- **Leaving a page while playing:** the player leaves a short-lived note (15 seconds) in localStorage. The player on the next page takes it and starts the same station. Pausing before leaving clears it.
- **Chrome and Edge:** the link click counts as the visitor's permission for sound, and the iframe's `allow="autoplay"` passes it on, so playback resumes on its own after about a second. Tested headless with Chrome's real autoplay policy: it resumed in 0.8-1.2s.
- **Firefox, Safari, or anywhere sound is blocked:** the station stays selected, the play button pulses, and the line reads *Tap ▶ to keep listening*.
- **Only one player plays at a time** across tabs and frames on the same site (via `BroadcastChannel`).
- **Truly gap-free playback** needs the site itself to swap page content without reloading, so the player is never reloaded. See [`docs/homerslotr-embed.md`](docs/homerslotr-embed.md).

## How it fits together

```
Station Manager (Electron) ──Save All──▶ stations.json + logos/   (this repo)
                                                │  git push
                                                ▼
                         GitHub Pages ── player.html ── fetches stations.json
                                                │
                https streams ◀─────────────────┤  direct
     http streams + metadata ◀── Cloudflare Worker (worker/) ── allowlisted by stations.json
```

- **`stations.json` is generated by the Manager. Don't edit it by hand.** In the Manager, set **Web Player Repo Root** to this folder and click **Save All**. That writes `stations.json` and copies each station's logo into `logos/`. Commit and push, and every embed picks up the change.
- **Why a proxy:** most stations only stream over plain `http://`, and browsers block http audio on https pages. The Worker relays those streams over https.
  - It also fetches and parses the Icecast/Shoutcast now-playing metadata, using the same logic as the Android `MetadataFetcher`. Most of those servers don't send CORS headers, so the browser can't read them directly.
  - Stations that are already `https://` play directly. If one fails, the player retries once through the proxy.
- **The Worker is not an open proxy.** It only relays stream and metadata URLs that appear in the published `stations.json`. It re-reads that file every 5 minutes, so a newly added station works shortly after you push.

|---|---|
| `index.html` | Demo / landing page with embed code |
| `player.html`, `player.css`, `player.js` | The embeddable player (no build step) |
| `config.js` | `PROXY_BASE`, the deployed Worker URL. On localhost it automatically uses `wrangler dev` |

| `worker/` | Cloudflare Worker (stream + metadata proxy) |

## One-time setup

1. **GitHub Pages:** in the repo, go to *Settings → Pages → Build and deployment*, set Source to *Deploy from a branch*, and pick `main` / `/ (root)`.
2. **Deploy the Worker** (needs a free Cloudflare account):
   ```bash
   cd worker
   npm install
   npx wrangler login
   npx wrangler deploy
   ```
   Wrangler prints the Worker URL, e.g. `https://slightly-epic-radio-proxy.<you>.workers.dev`.
3. Put that URL in `config.js` as `PROXY_BASE`, then commit and push.
4. Check it: `https://<worker-url>/health` should return `ok`. Play an http station (e.g. *EDM Techno Forever*) on the demo page.

`worker/wrangler.toml` sets `STATIONS_URL` to the GitHub Pages copy of `stations.json`. If you host the player somewhere else, change it there too.

## Local development

```bash
# terminal 1 — static files
python -m http.server 8080 --bind 127.0.0.1

# terminal 2 — the Worker, reading the local stations.json
cd worker
echo STATIONS_URL=http://127.0.0.1:8080/stations.json > .dev.vars
npx wrangler dev --port 8787 --ip 127.0.0.1
```

Then open http://127.0.0.1:8080/. `config.js` detects localhost and points at the local Worker.

## Bandwidth note

Every listener on an http station streams through your Worker (about 1 MB per minute at 128 kbps). Requests on the free Workers plan are capped per day, but one long-running stream counts as a single request, so a personal site should stay well within the limit.
